# Implementation contract

Status: executable local synthetic release, 27 October 2026. Existing detailed architecture diagrams describe the broader target; executable behaviour and acceptance receipts define what is implemented. This document records the implemented component contracts; source, tax and deployment adapters for production remain unresolved.

## Scope

Python 3.11+, FastAPI, SQLAlchemy 2, PostgreSQL 15+ (Docker target 17), separate database-backed worker, immutable filesystem objects in a dedicated volume, Parquet/DuckDB analytics, scikit-learn frozen Logistic Regression, actual LaTeX/PDF compilation, authenticated internal web UI. Synthetic simulation is the default. No actual customer data or emails.

## Synthetic source contract v1

Two CSV (or Parquet/XLSX) inputs named A and B represent independent one-to-one records for the same purchased service. This is an explicit TEST contract, not an assertion about the unknown real sources. Required fields: record_id, revision (positive integer), movement_id, customer_id, event_at (timezone-aware ISO), period (YYYY-MM matching event_at in UTC), currency (GBP initially), amount (nonnegative Decimal with at most 2 decimals), description, supplier_id. Additional point-in-time features: expected_amount (positive decimal), customer_age_days, supplier_age_days, hour_utc (derived), cross_border (0/1). Source identity comes from the ingestion argument, not a row. Financial values must not use binary float. Source record identity is (source, record_id, revision). Equal retries are no-ops; conflicting payloads quarantine. Multiple records claiming the same movement on a source are ambiguous and block billing. A is the authoritative amount ONLY under this demo contract; A/B disagreement blocks until an evidenced correction or source update.

Customers JSON: list of {id, legal_name, address, email, alert_email, vat_number}. All emails use example.test. Synthetic seller uses clearly invalid demonstration identity/tax/bank placeholders and every PDF is marked SYNTHETIC DEMO / NOT A TAX INVOICE.

## ML module interface

`features.py`: FEATURE_NAMES; `build_features(payload: dict) -> dict[str,float]` (no label, future or other-row dependency, missing required feature raises ValueError).
`ml.py`: `train_model(training_path: Path, output_dir: Path, *, activate: bool = True) -> dict`; `score_batch(payloads: list[dict], model_dir: Path) -> list[dict]` returns status (SCORED or UNAVAILABLE), score (float or None), flagged (bool), model_version, policy_version, feature_values, feature_schema_version, reason and an exact additive explanation when available. No I/O or failures may invent a zero score. Models are checksum-verified and cached by immutable artifact identity. Train/validation/test chronological split; exclude boundary rows with unavailable labels, fit scaler on train only, choose threshold on validation only, then report held-out synthetic test metrics. Numerical training work is capped at one native thread. Serialize trusted local artifacts only.

`model_readiness(model_dir, model_version=None)` verifies the artifact and serving pipeline; `activate_model(model_dir, model_version)` atomically publishes the active filesystem pointer. `explain_recorded(features, model_dir, model_version, expected_score, policy_version)` loads only the exact retained model and verifies score reconstruction. `compact_explanation(explanation)` supplies the small PostgreSQL receipt; full feature labels/parameters are expanded on demand. Contributions are log-odds, not percentage points or causal effects.

`model_ops.py`: `queue_training(db, rows, seed, period, request_id, actor)` creates a run and `TRAIN_MODEL` job in one transaction. The dedicated worker validates and trains a separate retained Parquet artifact, commits an exact activation intent before publication, verifies the active target and records success. `ACTIVATION_UNCERTAIN` blocks new runs and supports bounded automatic and explicit same-target recovery. Historical assessments are never rescored by activation. Legacy offline `direct_train` shares the admission lock and refuses to bypass an outstanding queued run; it does not provide queued activation recovery.

`generate_training_data(output_path, rows=30000, seed=42, serving_period='2026-09')` creates an independent ZSTD Parquet training file and manifest without modifying operational source files. The queued API/CLI accepts 1,000–50,000 rows; the low-level training function rejects more than 100,000. Synthetic labels remain outside serving inputs.
`synthetic.py`: `generate_dataset(output_dir: Path, customers: int = 8, movements: int = 2000, seed: int = 42, period: str = '2026-09') -> dict`. Produce customers.json, source_a.csv, source_b.csv, training.parquet (earlier period), manifest.json, scenario labels separately. Streaming bounded generator; offer largest-customer stress size flag without assuming aggregate 400M. Never include truth labels in serving feature payload. Controlled duplicate, mismatch, missing counterpart, invalid and high-risk examples. Do not write XLSX; root will create a bounded companion workbook via artifact tool.

## Invoice document module interface

`documents.py`: `render_invoice(document: dict, output_dir: Path, compiler: str = 'pdflatex') -> dict` returns pdf_path, tex_path, json_path, pdf_sha256. Caller supplies immutable already-validated document. Use Jinja2 template with fully escaped text and exact decimal formatting. Actual TeX compilation with shell escape disabled, timeout, logs retained. Never fallback to fake PDF.
Document fields: invoice_number, invoice_date, tax_point, due_date, period, currency, synthetic, seller {legal_name,address,vat_number,company_number,email,bank_name,account_name,sort_code,account_number}, customer {id,legal_name,address,email,vat_number}, lines [{description,quantity,unit_price,net_amount,vat_rate,vat_amount,gross_amount}], net_total, vat_total, gross_total, payment_terms, reference. Numeric amounts as decimal strings, rate fraction e.g. '0.20'. Reconcile line/group totals. Default full UK VAT invoice style in A4; non-VAT support if VAT disabled. Synthetic clearly not legally valid. Write templates/uk_invoice.tex.j2 and tests/test_documents.py; official requirements sources docs/UK_INVOICE_FORMAT.md.

## UI and deployment interface

Static English single-page operations console in templates/index.html, static/app.js, static/app.css. Routes: GET / (page), GET /health, POST /api/login {username,password}, POST /api/logout. Cookie session + CSRF token returned from login; send X-CSRF-Token on every unsafe authenticated request. POST /api/operators/bootstrap {setup_token,username,display_name,password} creates the first administrator atomically. Administrators manage subsequent personal accounts. Legacy POST /api/login {token} and the shared bearer token grant read-only access. The setup token is generated in .env by bootstrap, with no shared defaults. Cookies use a separate owner-only key in var/private/session-signing.key; knowledge of the shared setup token cannot sign personal cookies. Review actor identity comes exclusively from the personal server-validated session; no reviewer input field can override it.
Authenticated GET /api/dashboard -> {counts,mode,periods,model}; /api/customers -> list; /api/cases?status=OPEN&limit=100 -> list; /api/cases/{id} -> {case,movement,version,assessments,observations}; /api/invoices -> list; /api/outbox -> list; /api/audit -> list; /api/model -> metadata; /api/batches -> list.
POST /api/cases/{id}/correct {expected_version:int,patch:dict,reason:str,request_id:str}; /resolve {expected_version:int,outcome:'VERIFIED_VALID'|'CONFIRMED_ISSUE'|'UNRESOLVED',reason,request_id}. Verified-valid only clears MODEL concern, never deterministic failures.
GET /api/cases/{id}/model/explanation returns the recorded frozen-model calculation; POST /api/cases/{id}/model/preview {expected_version,patch} calculates a hypothetical copy without domain writes. The latter is the sole read-only calculation POST permitted to shared sessions, with normal origin/CSRF checks. POST /api/model/train {rows,seed,period,request_id} and /api/model/runs/{id}/retry {request_id} require an administrator. GET /api/model/runs is capped at twenty runs; verified retained training/manifest files are downloadable from their run. GET /api/model returns actual artifact readiness and a fresh worker-heartbeat observation. The queue and CSV support matching customer/status/reason/severity/prefix/score/sort filters. UI workbench memory is bounded to eight cases, comparison to three; inspect selection is independent of bulk release and every saved command retains its own expected version.
POST /api/close {customer_id,period,request_id}; /api/invoices/{id}/approve {fingerprint,request_id}; /revoke {reason,request_id}; /dispatch {request_id}. GET /api/invoices/{id}/pdf and /package -> immutable package JSON with PDF link. Package approval checkbox required client-side; server approves exact fingerprint. GET /api/exports/cases.csv and /dispatch.csv. POST /api/worker/tick (simulation only) -> counts; POST /api/simulation/events {attempt_id,event:'delivered'|'bounced'|'opened'}; POST /api/simulation/provider {outcome:'accepted'|'rejected'|'unknown'}.
API errors use JSON {detail:string or object}. Dashboard badges must label simulation and unknown. Display score unavailable distinctly from zero; provider accepted/delivered/opened separate. Avoid raw implementation clutter in user workflow; model/technical info can be separate tab.
Dockerfile includes actual TeX compiler. compose.yaml services postgres, api, worker, optional demo seeder profile. Same app image and shared data volume. Root writes config and CLI, command interfaces: `python -m invoice_optimizer init-db`; `serve --host 0.0.0.0 --port 8000`; `worker`; `demo --customers 8 --movements 2000`; `generate`; `train`; `ingest`; `close`; `export`; `benchmark`. UI agent can create Dockerfile/compose and .dockerignore, no root README. Do not create secrets or deploy remotely.

## Invariants

Database transactions make source checkpoints, outcomes, cases and jobs replay-safe. Workers use SKIP LOCKED/leases; uncertain external submission never automatically retries. Raw bytes retained, correction appends versions, actor/request IDs audited. Customer-period lock serializes ingestion, correction, close and issuance. Immutable snapshot membership, unique stable billable allocations, approval bound to exact PDF/message/from/to hash. Changes invalidate unissued drafts; issued changes require an explicit adjustment workflow and are blocked in v1. Monthly close requires both complete source manifests, exact coverage, no quarantine/open blockers and required scored/reviewed model status. Credit notes, FX, partial/split matching, production tax decisions and real source adapters are explicitly unsupported until contracted.
